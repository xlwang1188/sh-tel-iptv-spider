# 疑难排障与常见问题 FAQ

整理了在部署与使用本项目过程中可能遇到的典型问题及其深度排查方法。

---

### Q1: 为什么回看播放 38 秒就卡死，或者每 16 秒卡顿一次？
- **现象**: 播放器开始很流畅，但播放 16 秒或 38 秒后画面定格，进度条停止。
- **根本原因**: 电信 FonsView CDN 对单个长连接实施了流量整形（QoS），单个 TCP 连接传输满 23MB 后，带宽会被骤降至 240 KB/s（1.9 Mbps），而高清流需要 9.2 Mbps，导致播放器缓冲耗尽。
- **解决方案**: 本项目新版已内置切片流水线预读引擎，确保每个切片以独立的短连接并携带 `Range: bytes=0-` 拉取，避开限速区间，并在本地 SSD 保持 2 个切片的超前缓冲。请确保已升级至最新编译版本。

---

### Q2: 为什么测试时下载 300KB 数据后就彻底停滞断流？
- **现象**: curl 或播放器刚连上几百毫秒就断流，抓包显示服务端不再发送后续包。
- **根本原因**: **物理机顶盒依然开机并联网！**
  虚拟机克隆了物理机顶盒的 MAC 和 IP。由于机顶盒会周期性发送 mDNS/SSDP 广播，光猫内部交换机产生 **MAC 地址漂移**，将后续所有的视频流转发给了物理机顶盒，虚拟机端直接丢包超时。
- **解决方案**: **彻底拔掉物理机顶盒的网线或关闭机顶盒电源**。局域网内只能保留虚拟机一台设备使用该 MAC 地址。

---

### Q3: 为什么刚播完的节目点回看提示 `051003 未获取到节目播放地址`？
- **现象**: 在 EPG 点击刚刚结束（如结束仅 3~5 分钟）的节目回看时失败。
- **根本原因**: 电信机房录制系统在节目直播结束后，需要 **15 ~ 30 分钟** 的切片索引与分发处理期。在此期间，点播服务器尚未收录该节目的完整 HLS 播放列表。
- **解决方案**: 这是电信服务端的数据生成延迟。请稍等约 15~30 分钟后再点播该节目；或者点播该节目播出前半段、昨天/前天的节目，即可秒开。

---

### Q4: 电视机只有 100 Mbps 百兆网卡，会成为回看瓶颈吗？
- **完全不会**。
- CCTV-5 等 1080P 高清频道码率为 **9.2 Mbps**。百兆网卡（100 Mbps）具有 **10 倍以上** 的余量空间。
- 在百兆有线下，电视机从部署在内网的虚拟机拉取一个已缓存的 10 秒分片（11MB）仅需 **0.9 秒**，播放速度是下载速度的 1/10，绝不会发生缓冲饥饿。

### Q5: 组播直播（Live）无法播放或黑屏？
- **排查步骤**:
  1. 检查 `udpxy` 服务是否正常运行：
     ```bash
     ps aux | grep udpxy
     ```
  2. 检查组播路由是否已添加至 `eth0.85` 网卡：
     ```bash
     ip route show | grep 239
     # 必须存在：239.0.0.0/8 via 30.120.0.1 dev eth0.85
     # 必须存在：233.18.204.0/24 via 30.120.0.1 dev eth0.85
     ```
  3. 测试 udpxy 直通取流：
     ```bash
     curl -i "http://172.16.0.5:5140/rtp/233.18.204.188:5140" | head -c 1000
     ```
     如果能收到以 `0x47`（ASCII 'G'）开头的二进制数据，说明组播完全正常。

### Q6: 多台设备同时观看回看，磁盘空间会爆满吗？
- **不会**。
- 缓存引擎内部实现了严格的 **LRU 淘汰机制**，默认上限 `MaxCacheFiles = 30`（总容量约 300MB）。
- 当分片超过 30 个时，系统会自动清理最久未被访问的切片，始终将磁盘占用控制在 300MB 以内，在任何低配虚拟机/软路由上都能常年无人值守稳定运行。

### Q7: 为什么 TiviMate（特别是在 2.x 等老版本上）点回看报错“出现一处错误，代码 404”？
- **现象**: 在 TiviMate 节目指南上挑选过去的节目点击播放，屏幕弹出红色提示：“出现一处错误，代码 404”。
- **根本原因**:
  1. 如果 M3U 或 TiviMate 设置中开启了 `Flussonic` 协议，TiviMate 会**完全忽略** M3U 里配置的 `catchup-source` 模板，而是尝试直接重写直播流地址（`http://172.16.0.5:5140/rtp/...`）的末尾路径，将请求发往 `rtp2httpd` 监听的 **5140 端口**。
  2. `rtp2httpd` 是极简的 C 语言组播代理，根本不提供回看服务，试图解析名为 `index-...` 的组播 IP 失败后自然返回 HTTP 404。
- **解决方案**:
  1. **代码层已内置修复**: 自动注入标准 `catchup="default"` 标签并支持 `${start}`、`{utc}`、`${(b)yyyyMMddHHmmss}` 多种方言，并在后端支持时间窗口智能兜底；
  2. **TiviMate 设置检查**:
     - 进入 `设置` -> `播放列表` -> 点击你的播放列表；
     - 进入 `回看 (Catch-up)`；
     - 将 **类型 (Type)** 选择为 **“自动 (Auto)”** 或 **“默认 (Default)”**；
     - **回看源 (Catch-up source)** 留空即可；
     - 返回上一级点击 **更新 (Update playlist)** 重新同步即可恢复完美回看。

### Q8: 为什么部分省级卫视回看画质非常低且画面比例是 4:3？
- **现象**: 东方卫视、广东卫视回看都是正常 1080P 16:9，但湖南卫视、江苏卫视、北京卫视、四川卫视回看却是 720x576 标清且比例被压成 4:3，浙江卫视甚至报 404。
- **根本原因**:
  1. 电信 IPTV 平台对于各大卫视同时提供了**高清（HD，1080P，如 mixNo=143 湖南卫视HD）**与**标清（SD，576i，如 mixNo=203 湖南卫视）**两种源；
  2. 原程序在抓取 EPG 节目单时，采用了不恰当的 SQL 去重语句：`SELECT MAX(code), MAX(ch_id), comm_name FROM channel_infos GROUP BY comm_name`；
  3. 由于标清频道的 `ch_id` 字符串（如湖南标清 `ch...1501`）恰好比高清频道（`ch...1424`）字母序更大，SQL 聚合查询错误地选取了**标清频道的 ch_id**，导致抓取入库的全部是标清频道的节目单 `playbillID`；
  4. 随后播放器发起回看请求时，电信 TVOD 点播集群接收到的是标清节目单 ID，因而下发了 **720x576 4:3 标清回看流**；而浙江卫视因高清频道与标清节目单 ID 不匹配直接返回了 404。
- **解决方案**:
  - 重构了 EPG 频道选取算法，严格按照 `is4_k DESC, is_hd DESC` 优先级进行频道排序与去重；
  - 确保抓取 EPG 节目单时，永远强制选取 **4K / 高清** 频道的完整记录（code、ch_id 全套成对匹配）；
  - 回看点播匹配时同步遵循 4K/HD 优先原则，全量省级卫视回看现已全部升级为 **1920x1080 Full HD、16:9** 超清画质。

### Q9: 省级4K卫视（江苏4K、浙江4K等）回看是如何实现真4K的？
- **背景与痛点**:
  - 在上海电信 IPTV 官方点播库中，**仅有 CCTV-4K（124频道）** 拥有独立的 4K HLS 节目单回看切片；
  - 省级卫视 4K 频道（601东方、641浙江、642江苏、643湖南、644北京等）在电信 EPG 点播库中并没有独立 4K 节目单，若走点播回看会被降级为对应的 1080P 高清切片；
  - 但经过深度探测，电信 CDN 针对 600 系列 4K 频道在底层 RTSP 时移系统（TimeShift 滚动缓存）中完整保存了长达 **6天（144小时）** 的 **3840x2160 @ 50fps HEVC、杜比 AC-3** 顶级画质码流！
- **智能分流机制**:
  1. **EPG 绑定**: 在 M3U 中，4K 卫视频道复用其对应高清频道的 `tvg-id`（如江苏4K使用 `tvg-id="142"`），使 TiviMate 能完整展示节目单与回看入口；
  2. **精准回看路由**: 在生成的 `catchup-source` 模板中，系统自动为 4K 频道注入专属参数 `channel_id=642&mode=timeshift`；
  3. **4K 时移直通**:
     - 当收到 4K 频道的回看请求时，系统自动绕过被降级的 1080P TVOD 切片，直接将请求重定向至 `rtp2httpd` 的 RTSP 时移代理；
     - 客户端直接拉取电信原生的 **4K 50fps HEVC** 时移 TS 流，回看与直播画质完全一致；
  4. **央视 4K 保留 HLS**: 对于央视 CCTV-4K，由于电信官方点播库本身即为原生 4K HLS，系统自动保留 4K HLS 模式，兼顾 4K 画质与毫秒级进度拖拽。
