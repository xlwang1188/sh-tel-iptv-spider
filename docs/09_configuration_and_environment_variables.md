# 系统功能清单、配置参数详解与隐私安全规范

本项目提供了一套完整的**上海电信 IPTV 组播直播、单播回看加速、EPG 抓取与切片预热代理**系统。本文档全面梳理本系统能够实现的核心功能、网络与环境参数清单、配置方法，以及基于环境变量（`.env`）的隐私脱敏方案。

---

## 1. 系统核心功能清单与实现效果

经过深度逆向与流媒体流水线优化，本系统实现了以下核心能力：

### 1.1 组播直播转单播（Live Multicast to Unicast）
- **功能**: 将电信专网 VLAN 85 内的 IGMP/RTP 原始组播流转化为局域网标准 HTTP 单播流。
- **性能**: 借助 `rtp2httpd` 专用内核态套接字和零拷贝技术，支持极高并发与 4K 超高清（如 CCTV-16 4K、东方卫视 4K，码率高达 25~35 Mbps），实测零花屏、零丢包。
- **终端兼容**: 局域网内任意手机、电脑（VLC/IINA）、智能电视或电视盒子（Tivimate、Kodi、Apple TV）均可免机顶盒直接观看。

### 1.2 动态鉴权与时移回看代理（TVOD Catch-up & Timeshift）
- **功能**: 
  - 自动模拟机顶盒与电信 EPG 业务网关握手，动态下发并维持 Session Token；
  - 接收播放器标准 `playseek` 时间参数，向电信 TVOD 接口请求目标节目单切片列表；
  - 将上游电信带有鉴权防盗链的 M3U8 索引重写为本地代理链接，客户端无需任何凭证即可免密点播过去 7 天内的任意电视节目。

### 1.3 深度流水线切片预热与毫秒级本地缓存（Lookahead Prefetching Cache）
- **痛点解决**: 电信 CDN 对单个 IP 下发连接有初始握手延迟，且客户端逐片拉取时容易在切片交界处发生卡顿（16秒或30秒卡死）。
- **创新实现**:
  - **HTTP Range 突破**: 主动注入 `Range: bytes=0-`，将切片下载速度直接拉满至物理/网关极限（实测 92~106 Mbps 瞬间突发下载）；
  - **深度为 2 的预热链**: 客户端请求第 N 片时，后台预热协程已在静默并行预下载第 N+1 片与第 N+2 片；
  - **毫秒级响应**: 客户端后续请求击中本地缓存，响应时间仅需 **17ms ~ 28ms**，彻底终结回看卡顿与等待转圈；
  - **动态 LRU 淘汰**: 维护高效环形缓存（默认保留 30 个切片，约 300MB），自动根据访问时间清理旧切片，零磁盘溢出风险。

### 1.4 多客户端独立并发播放（Multi-client Concurrency）
- **验证结论**: 经过实机并发压力测试，电信平台对同一 IPTV 账号回看**未限制单流锁死**。
- **并发能力**: 局域网内多台电视（如客厅电视回看 CCTV-5+，卧室电视回看 CCTV-1）可同时点播不同或相同的节目，总吞吐可达 160+ Mbps 以上，互不干扰、互不卡顿。

### 1.5 自动化 EPG 节目单抓取与台标匹配
- **功能**: 定时（Cron）自动抓取上海电信全量电视频道及近 7 日节目单，生成标准 XMLTV 格式文件（`/api/epg.xml`）。
- **静态台标库**: 内置 200+ 常见电视频道高清 PNG 台标，自动拼接台标 URL，Tivimate 订阅后即可呈现精美节目指南。

## 2. 外部依赖与网络环境要求

要复现本系统，硬件与网络需满足以下条件：

| 组件 / 节点 | 要求与建议 | 说明 |
| :--- | :--- | :--- |
| **电信光猫** | 开启 IPTV VLAN 85 单线复用或独立网口 | 必须能够获取到电信 IPTV VLAN 85 数据 |
| **宿主机 (ESXi/PVE/物理软路由)** | 双网卡（或单网卡+VLAN交换机） | 网卡 1 接电信专网 VLAN 85，网卡 2 接家庭局域网 LAN |
| **系统环境** | Linux (推荐 Alpine Linux 3.20/3.21) | 极简安全，内存仅需 256MB~512MB 即可跑满多路流 |
| **组播代理** | `rtp2httpd` (首选，本项目已附一键安装包) 或 `udpxy` | 负责 RTP/UDP 组播转 HTTP 协议 |
| **客户端播放器** | Tivimate (Android TV 首选) / Kodi / PotPlayer / VLC | 支持标准 M3U 播放列表及 XMLTV 节目指南 |

## 3. 核心参数清单与获取方法

本系统的参数可分为**“环境私密参数”**（机顶盒专有）与**“网络服务参数”**（局域网部署专有）：

### 3.1 隐私敏感参数（必须按自家环境提取）

| 环境变量名 | 示例值 | 含义与说明 | 获取来源 / 提取方式 |
| :--- | :--- | :--- | :--- |
| `STB_UID` | `4833xxxx@etv4` | 电信 IPTV 业务账号 | ① 机顶盒设置中查看“业务账号”<br/>② 抓包 HTTP 请求参数中的 `u=` 或 `uid=` |
| `STB_MAC` | `18:5e:0b:xx:xx:xx` | 真实机顶盒网卡物理 MAC | 机顶盒背面条形码标签，或抓包中 Ethernet 帧源 MAC 地址 |
| `STB_SN` | `00030032540702305260xxxx` | 真实机顶盒唯一设备序列号 | 机顶盒背面标签，或抓包中 `stbid=` 字段 |
| `STB_IP` | `30.120.xx.xx` | 电信内网 IPoE 分配给盒子的 IP | 机顶盒网络设置中查看，或抓包中 IP 报文源地址 |
| `STB_TYPE` | `B860AV2.1-T` | 机顶盒型号代码 | 机顶盒外壳铭牌（如中兴 B860AV2.1-T、华为等） |
| `STB_AUTH_HOST` | `222.68.208.73:7001` | 电信 EPG 认证网关地址 | 上海电信统一网关，抓包开机首个 POST 请求域名/IP |

> [!CAUTION]
> **绝对注意事项**:
> 提取完上述信息后，**必须将物理机顶盒彻底断电或拔掉网线**！否则物理机顶盒发出的后台心跳广播会导致交换机发生 **MAC 漂移**，导致虚拟机的切片下载瞬时被掐断。

### 3.2 局域网服务与路径参数

| 环境变量名 | 默认示例 | 含义与说明 |
| :--- | :--- | :--- |
| `SYSTEM_ADDR` | `0.0.0.0:8888` | IPTV Spider HTTP 监听地址及端口 |
| `CACHE_DIR` | `/home/xlwang/hls_cache` 或 `./hls_cache` | TS 切片预热本地存储目录（建议 SSD 或 tmpfs） |
| `EPG_XML_URL` | `http://172.16.0.5:8888/api/epg.xml` | 客户端订阅 XMLTV 的局域网访问地址 |
| `EPG_RTSP_URL`| `http://172.16.0.5:5140/rtsp/` | rtp2httpd 的 RTSP 转流前缀 |
| `EPG_RTP_URL` | `http://172.16.0.5:5140/rtp/` | rtp2httpd 的 RTP 组播转流前缀 |
| `EPG_LOGO_URL`| `http://172.16.0.5:8888/logo/` | 台标图片访问前缀 |
| `EPG_FETCH_CRON`| `0 0 8,16,23 * * *` | 每日定时更新节目单的 Cron 表达式 |

## 4. 环境变量机制（.env）与隐私脱敏

为保证用户可将代码放心地开源至 GitHub 或分享给他人，系统实现了**配置与凭证解耦机制**：

### 4.1 优先级顺序
系统配置的加载优先级如下：
1. **环境变量 / `.env` 文件**（最高优先级，直接覆盖所有内存配置）；
2. **本地 `config.yaml` 配置文件**；
3. **公共模板 `config.example.yaml`**（当未提供 `config.yaml` 时的回退默认配置）。

### 4.2 `.gitignore` 安全防护
Git 忽略规则已经配置为安全策略：
```gitignore
# 忽略所有私密配置和环境变量
config.yaml
config.local.yaml
.env
.env.*

# 仅保留公开示例模板供他人参考
!.env.example
!config.example.yaml
```

### 4.3 新环境部署与使用步骤
在新机器上拉取代码后，无需修改任何已跟踪的代码文件，仅需两步即可运行：

```bash
# 1. 从模板复制出私有环境变量文件
cp .env.example .env

# 2. 编辑 .env 文件，填入您自己的机顶盒账号与网络 IP
vim .env

# 3. 运行程序（程序启动时将打印 "成功载入环境变量配置文件: .env" 并生效）
./iptv-spider
```
